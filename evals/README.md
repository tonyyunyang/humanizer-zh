# 中文行为回归

[`cases.json`](cases.json) 是一组合成场景，覆盖自然度和容易被误改的边界。它是维护用的回归材料，不是“去 AI 味成功率”榜单。

持续改进的方法、文本前测命令和提交规则见[改进循环](../docs/RSI.md)。新增的独立案例放在 `rounds/`，实际输出和逐轮判断放在 `runs/`；执行成功与编辑质量通过分开记录。

## 怎么用

在你准备支持的工具和模型中，只加载本项目的 `SKILL.md`，逐个给出案例的 `request`、可选 `sample` 和 `input`。每个案例开独立会话，不把 `expectations` 给改写模型。需要文件输入的案例，在临时目录创建测试文件后传给模型，不使用用户的真实文件。

保存模型原始输出，再对照 `expectations` 审阅。事实、归属、条件、引用或技术内容被改变，直接记为失败；不能用“读起来更顺”抵消。通过允许多种表达，不要求字符串命中某个标准答案。

至少核对：

- 输入中的实质信息在输出中是否完整，输出是否增加了输入没有的断言。
- 立场、完成状态、限定条件和责任是否一致。
- 该删的空话是否处理，该留的文体和自然表达是否保留。
- 只标问题和文件编辑请求是否遵守交付范围。

修改一条规则时，先跑与它有关的场景和保留反例；发版前完整回归。如果声称支持多个模型，应记录各模型实际结果，不能只给一个合计分数。

## 怎样记录

PR 或版本评测记录至少包含：skill 提交 SHA、工具和模型的可识别版本、日期、是否使用样文、逐例原始输出、逐例通过/失败及理由。另请说明是否由改写者自己审阅；自查不等于独立评测。

安装校验、Python 单元测试、说明性示例都不能记成模型行为测试。仓库初始版本提供这组场景与编辑示例，**没有宣称独立模型评测已经通过**。

真实案例可后续加入，但应先获得公开许可、去掉私人信息。不要上传 API key、完整私有日志或未经授权的文章。
