# 第二轮：保留作者已有的立场限定

本轮保留修订 `9d4b42b` 中的写作规则：区分“不必新增”和“删去已有”，并用一个个人立场的保留例子补充说明。修订后的 skill 共 154 行。上轮增加的说明文分组提示已撤回。

## 发现与修改

第一轮保留例中，用户要求不在结尾新增平衡各方的道理，原文同时写明别人喜欢打卡是别人的自由，文章只解释自己的退出。基线 `a03e047` 和首个候选 `8cb2e9b` 都删掉了这层已有的立场限定。维护者回查了完整请求和输出，确认这是信息保留问题，而非必须保留某个句式的审美偏好。

修订只增加一个短段落和一个保留例子。已有的解释、让步和立场限定要留下；用户明确要求删去的部分仍照常删除。没有新增词语黑名单，也没有规定文章必须加一段平衡说明。

## 验证结果

编辑与匿名评审均使用 Codex CLI `0.153.4`、`gpt-6-astra`、`max`，每次新会话。基线为 `a03e047`，候选为 `9d4b42b`。编辑器未收到预期答案；匿名评审未收到版本身份或修改说明。

重复检查的 4 次基线输出包含第一轮失败输出、本轮首次输出及两次额外重复；3 次候选输出包含本轮首次输出和两次额外重复。请求改述没有混进这组计数。最初的失败由独立评审发现，本轮首次对照由匿名模型评审判断，额外重复由维护者逐一回读；样本仍然很小，不能据此估计可靠的错误率。

在普通文风偏好上，4 个开发回归任务为双方各 1 次较好、2 次平局；8 个新案例为基线 1 次较好、7 次平局。因此，本轮采纳的是针对已观察到的信息丢失所作的范围提醒，不声称整体文风已经显著超过基线。

完整计数、逐例判断与重复检查路径见 [summary.json](summary.json)。原始输出位于各运行目录，匿名任务和身份映射分开保存。对较长比较任务，评审超时设为 300 秒，生成任务仍为 180 秒；两侧生成设置相同。

## 保留集与局限

第二轮的八个新案例由独立会话 `fresh_round2_cases` 在候选固定后编写，出题者没有读取 skill、已有案例、输出或失败记录。生成了 4 个开发例和 4 个保留例。两分区一起批量执行，但每例仍是独立会话，分区信息和预期未交给编辑器；候选没有根据新案例再调整。

第一轮的失败例已转为本轮开发材料，本轮所有案例也已消耗，后续不能继续称作未见测试。使用的都是合成文本、同一模型家族，尚未包含真实作者的盲评，也没有建立 Claude Code 或其他模型的效果结论。

第一轮已验证基线版本的真实文件编辑；本轮没有把这项历史结果记作新修订的再次实测。正式发布前仍应在目标工具中做全量回归。

## 下一轮起点

将本轮修订作为新的本地起点，优先收集真实使用中的失败或不同模型的分歧，不再围绕已经通过的样文反复换词。新增永久回归项 `zh-27`、`zh-28` 分别覆盖已有立场限定与明确删句的例外。历史运行的案例文件版本以其 manifest 哈希及对应 Git 历史为准，不能用更新后的 28 例文件冒充当时的 26 例输入。
