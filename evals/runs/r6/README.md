# 第六轮：完整、精简与无 skill 的对照

本轮根据 [OpenAI 关于 GPT-6 Astra 的提示与 skill 建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，检查已有指导是否有实际价值，以及较短版本能否保留它的作用。文章提出的是待验证的方向，不是本轮结果。

## 固定条件

| 条件 | 编辑指导 | 固定版本 |
| --- | --- | --- |
| 完整版 | 已认可的 178 行 skill，5346 字符、14480 字节 | `ce8cd106fb5df3312a6141e7972e0391f474277b` |
| 精简版 | 同样的元数据与编辑目标，合并重复指导、减少说明性例子；71 行、2079 字符、5697 字节 | `3acd0c466504562ed57e9a5851f5d3ee5d821ce5` |
| 无 skill 对照 | 不注入 humanizer-zh，只给相同的用户请求、原文及可选样文 | `--skill-ref none` |

精简版在独立案例编写前已经固定。为维持单一运行入口，候选仅通过 Git 提交取用，工作树先恢复已认可的完整正文。没有新增第二份 skill，也没有改安装结构。实验在本地 `codex/rsi-r6` 分支，保留手动启动方式。

无 skill 对照仍使用相同的 Codex 基础指令和文本任务外层提示，不是去掉所有系统指令的裸模型实验。本轮检验明确加载后的效果，不检验 skill 自动发现或选择。

## 材料与运行

- 六份不同的中文或中英混排原文，三项开发、三项保留；覆盖普通文字、表达性文字、技术材料和协作说明。出题会话不读任何版本、旧案例或评审提示。
- 用户请求保持日常表达，不人为重复完整编辑规范。验收要点只作为检查提示，须由真实请求和原始材料支持。
- 三种条件使用同一批材料、同一 `gpt-6-astra` 模型、`max` 推理设置、同一 CLI 与运行器版本。每项每条件先生成一份，独立临时会话，编辑超时 240 秒。
- 三组生成重叠运行，每组单任务并发，降低先后批次的时间差。保留每次用量、耗时、提示与版本哈希；无法控制的服务时序和模型波动仍是限制。
- 完整/精简、完整/无 skill、精简/无 skill 三组均作匿名成对比较，共 18 次初评；沿用第五轮修正后的评审口径，评审超时 300 秒。
- 全轮最多 48 次编辑或评审调用，包含失败重试。初始 18 次编辑加 18 次比较，最多再用 6 次顺序复核及 6 次重复或恢复检查。优先复核信息/范围问题，再按固定的案例 ID 与配对名称选取非平局项目；未复核的偏好不能作为稳定收益。

## 判断与取舍

先看信息、范围和任务完成，再看具体中文表达、作者声音、模板痕迹及协作可用性。不能以更短的成稿、更少的标题或更多修辞作为统一赢家；比较中不向评审提供版本名称、指导长度或改动说明。

上下文占用单独报告。固定指导的字符和字节减少是可复核的结构差异；模型返回的输入 token、输出 token 和耗时只作为本轮实测，不直接换算成通用速度或价格保证。

这轮不根据开发组结果修改精简版，再拿同一保留集宣称泛化。出现实质回退时先核对并重复必要案例，记录对当前候选的限制。平局或全部通过不足以证明整体等效，尤其不能由六个样例推断无 skill 在其他模型或场景也足够。

实验结束后决定保留、修订或撤回候选。结论不清时继续保留已认可的完整版，并保存精简版的可回溯提交；不为制造一次改进而删减正文。
