# 第六轮：完整、精简与无 skill 的对照

本轮根据 [OpenAI 关于 GPT-6 Astra 的提示与 skill 建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，检查已有指导是否有实际价值，以及较短版本能否保留它的作用。文章提出的是待验证的方向，不是本轮结果。

**取舍：继续保留 178 行完整版。** 71 行候选减少了本轮 17.2% 的总输入 token，但六个短案例不足以证明整体等效。完整版在一项回复的具体措辞上略占优，无 skill 对照则在操作步骤的组织上更好；没有一个条件在所有方面都更好。候选和全部证据已保存，不据此新增禁词或固定格式。

## 固定条件

| 条件 | 编辑指导 | 固定版本 |
| --- | --- | --- |
| 完整版 | 已认可的 178 行 skill，5346 字符、14480 字节 | `ce8cd106fb5df3312a6141e7972e0391f474277b` |
| 精简版 | 同样的元数据与编辑目标，合并重复指导、减少说明性例子；71 行、2079 字符、5697 字节 | `3acd0c466504562ed57e9a5851f5d3ee5d821ce5` |
| 无 skill 对照 | 不注入 humanizer-zh，只给相同的用户请求、原文及可选样文 | `--skill-ref none` |

精简版在独立案例编写前已经固定。为维持单一运行入口，候选仅通过 Git 提交取用，工作树先恢复已认可的完整正文。没有新增第二份 skill，也没有改安装结构。实验在本地 `codex/rsi-r6` 分支，保留手动启动方式。

无 skill 对照仍使用相同的 Codex 基础指令和文本任务外层提示，不是去掉所有系统指令的裸模型实验。本轮检验明确加载后的效果，不检验 skill 自动发现或选择。

## 材料与运行

- 六份不同的中文或中英混排原文，三项开发、三项保留；覆盖普通文字、表达性文字、技术材料和协作说明。出题会话不读任何版本、旧案例或评审提示。
- 用户请求保持日常表达，不人为重复完整编辑规范。验收要点只作为检查提示，须由真实请求和原始材料支持。
- 三种条件使用同一批材料、同一 `gpt-6-astra` 模型、`max` 推理设置、同一 CLI 与运行器版本。每项每条件先生成一份，独立临时会话，编辑超时 240 秒。
- 三组生成重叠运行，每组单任务并发，降低先后批次的时间差。保留每次用量、耗时、提示与版本哈希；无法控制的服务时序和模型波动仍是限制。
- 完整/精简、完整/无 skill、精简/无 skill 三组均作匿名成对比较，共 18 次初评；沿用第五轮修正后的评审口径，评审超时 300 秒。
- 全轮最多 48 次编辑或评审调用，包含失败重试。初始 18 次编辑加 18 次比较，最多再用 6 次顺序复核及 6 次重复或恢复检查。优先复核信息/范围问题，再按固定的案例 ID 与配对名称选取非平局项目；未复核的偏好不能作为稳定收益。

## 判断与取舍

先看信息、范围和任务完成，再看具体中文表达、作者声音、模板痕迹及协作可用性。不能以更短的成稿、更少的标题或更多修辞作为统一赢家；比较中不向评审提供版本名称、指导长度或改动说明。

上下文占用单独报告。固定指导的字符和字节减少是可复核的结构差异；模型返回的输入 token、输出 token 和耗时只作为本轮实测，不直接换算成通用速度或价格保证。

这轮不根据开发组结果修改精简版，再拿同一保留集宣称泛化。出现实质回退时先核对并重复必要案例，记录对当前候选的限制。平局或全部通过不足以证明整体等效，尤其不能由六个样例推断无 skill 在其他模型或场景也足够。

实验结束后决定保留、修订或撤回候选。结论不清时继续保留已认可的完整版，并保存精简版的可回溯提交；不为制造一次改进而删减正文。

## 上下文实测

以下只统计第一批六个匹配案例，不混入后续针对性重复。完整数据见 [measurements.json](measurements.json)。

| 条件 | skill 字符数 | 平均输入 token | 单次耗时中位数 |
| --- | ---: | ---: | ---: |
| 完整版 | 5346 | 13456.8 | 23.46 秒 |
| 精简版 | 2079 | 11144.8 | 28.53 秒 |
| 无 skill | 0 | 9581.8 | 22.33 秒 |

精简版的指导字符减少 **61.1%**，但本轮总输入只减少 **17.2%**，平均每次少 2312 token。相对无 skill 对照，完整和精简指导分别增加约 3875 和 1563 token；这些差值包含注入指导时的外层提示与元数据，不能等同于纯正文的分词结果。

本轮没有显示精简版更快。耗时还受推理长度、缓存、进程与服务状态影响，六次的中位数不能用来保证通用速度或费用。

## 材料能说明什么

独立案例是养花自嘲、阅览室通知、worker 启动说明、review 回复、买家回复校对与退款入口进展。六篇都较短，原文大多已经能读懂；通知和校对本来就适合少改。这能检查日常修改、技术含义、轻微表现力和范围遵守，但不足以检验长篇套话、复杂叙述声音或大幅提升文学表达。

所有版本都在出题前固定，本轮没有根据开发组结果调整候选。保留组也只有三项，看完后都成为已使用材料。针对已发现问题的重复不是新的保留案例，不能扩充成更多独立样本。

## 实际结果

共完成 **47 次有效执行**：18 份初始改稿、18 次匿名比较、5 次顺序复核、3 份针对性重复改稿、3 次重复稿比较，没有失败或恢复调用，未超过预设的 48 次上限。执行有效不等于写作通过。机器可读汇总与逐项来源见 [summary.json](summary.json)，后续检查在运行前固定于 [followup-plan.json](followup-plan.json)。

18 次初评有 13 次平局。以下保留模型的原始偏好，包含存在信息争议的判断，不直接当作版本胜率。

| 初始比较 | 偏好前者 | 偏好后者 | 平局 |
| --- | ---: | ---: | ---: |
| 完整 / 精简 | 1 | 0 | 5 |
| 完整 / 无 skill | 1 | 1 | 4 |
| 精简 / 无 skill | 0 | 2 | 4 |

阅览室通知与买家回复校对，两例的三种输出分别完全相同。养花自嘲和进展说明的三组比较也都判为平局，差别主要在断句和分段。所有评审都未定位到具体的模板残留；这只反映本批成稿与评审结果，不是“去 AI 味成功率”。

五项非平局全部交换 A/B，再开独立会话评审：

| 案例与比较 | 初评偏好 | 互换后偏好 | 含义 |
| --- | --- | --- | --- |
| review 回复：完整 / 精简 | 完整 | 完整 | “恢复按钮状态”比“状态恢复”更具体，差距小 |
| worker 说明：完整 / 无 skill | 无 skill | 无 skill | 编号步骤更便于新同事照做、回查 |
| worker 说明：精简 / 无 skill | 无 skill | 无 skill | 同一份操作说明、同一结构优势，不是第二个独立案例 |
| review 回复：完整 / 无 skill | 完整 | 无 skill | 同时发生信息门槛与偏好反转 |
| review 回复：精简 / 无 skill | 无 skill | 无 skill | 偏好方向相同，但同一无 skill 稿在另一配对中存在信息争议 |

顺序复核的输入与映射见 [swapped/](swapped/)。四项偏好方向一致，一项反转；其中有方向一致的判断涉及争议稿，不能只按票数记成稳定收益。复核同时换了顺序和随机生成的评审会话，无法把反转单独归因于位置偏差。

### 判断余地的争议与重复

原文是“把按钮 disable 掉**应该能**挡住当前页面上的重复提交”。无 skill 首稿改为“禁用按钮，**可以避免**当前页面因连续点击而重复提交”。完整与精简首稿均保留“应该能”。

同一份无 skill 首稿在四次相关判断中出现一次 fail、三次 pass；其余 17 份初始改稿仅收到 pass。维护会话回到原文后，认为“可以避免”把预期效果提高成了能力断言，值得保留为信息问题；这一复核已看到版本身份，不是外部人工盲评，也不覆盖原始模型判断。完整的推理及边界见 [source-review.json](source-review.json)。

随后对该案例的三种条件各重复生成一次，提示哈希与各自首轮完全相同。重复稿的三次匿名比较全部通过信息门槛；偏好为完整优于精简、无 skill 优于另外两者，主要理由仍是恢复对象和按钮行为是否具体。每对重复稿仅评一次，没有继续互换，不能独立确立稳定收益。

无 skill 重复稿写成“**我想先补上**……，**避免**当前页面内因连续点击造成的重复提交”。这里可理解为拟议工作的目的，没有重现首稿同样的能力断言。不能只因没写“应该”就判失败，也不能把一次未重现当作风险已消失。重复稿中针对具体提醒说“感谢提醒”，也符合用户要求的合作语气，不应当作助手套话删除。

## 本轮决定与限制

保留完整运行正文及其现有例子，71 行候选停留在 `3acd0c4`。本轮支持继续研究精简，不支持立即替换：样本太小，最明显的模板和表现力难题尚未覆盖；完整版在一个回复中的措辞优势较稳定，但同样不能外推为全面更好。

无 skill 对照的表现说明，不能把所有顺畅表达都归功于 humanizer-zh。两份 skill 都已允许有用的步骤和层级，仍未在此例中采用更方便操作的编号；仅凭这一例，不增加“操作说明必须编号”的规则。本轮也无法确定哪一条指导或哪个例子造成了差异，因为精简同时改变了多处内容。

下一轮如继续，优先补充明显模板化的较长文字，以及需要改善表现力、同时保留作者声音的材料，并使用候选固定后才编写的新案例。现有六例转为开发材料。模型评审对判断余地的处理仍需校准，可将能力断言与行动目的做成相邻反例；不能通过改评分后更容易通过，就宣布正文进步。

本轮只覆盖 `gpt-6-astra`、`max` 与记录中的 Codex 基础指令。同一模型的独立会话可能共享偏好，没有外部中文编辑盲评，也没有重新检验文件编辑、自动调用或其他模型。不声称最佳、整体等效、通用速度提升或 AI 检测能力。

本轮实验在分支 `codex/rsi-r6` 完成，继续保留已认可的 178 行正文，没有恢复已删除的 RSI 定时任务。维护脚本只改了 `--skill-ref` 的帮助文案；仓库校验及 29 项单元测试通过，不能将这些检查计入写作成绩。
