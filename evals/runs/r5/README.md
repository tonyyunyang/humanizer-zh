## 固定起点与问题

- 本轮最多 30 次编辑或评审调用，包含校准、重复检查、失败重试和必要的顺序复核。达到上限就保留已有结果，不以未完成数据宣布改进。

## 先审查起点

第三、四轮的文风偏好不稳定。本轮先单独检查基线输出的保真、范围和任务完成情况，不预先增加一条规则再为它寻找理由。单稿评审用独立的 JSON schema 记录具体证据，并用两个预先声明结果的校准任务检查其是否区分缺失材料与作者已提供的陈述。校准不计入 skill 行为收益。

只有实际输出出现可说明的问题，才考虑候选。实质信息或范围错误需回到原文核对并做必要的重复检查；纯审美差异不够成为通用规则。出现候选时，沿用原有匿名比较方法，再用保留组检查；一个问题最多两个候选。

开发组没有明确问题时，以原基线继续检查保留组，允许整轮不改 `SKILL.md`。新案例、校准方法与诚实的验证记录也应提交。起点表现良好只支持当前案例，不是已经达到所有场景最优的证据。

## 前测与校准

六个独立案例已在 `6dfe6fa` 固定。三个基线开发输出均通过修订后的独立单稿审查，任务完成情况均为 adequate，未发现可定位的无效模板问题。此时决定不修改 skill，以原基线 `df030ac` 进入保留组；保留组内容在这一决定前未打开。

首次单稿校准中，作者陈述案例符合预期；缺失验证记录案例虽然被指出无依据，却被标为 uncertain，而预先声明的结果是 fail。这个差异涉及评审口径：无法断定现实中的真假，并不使无依据的新增事实符合编辑要求。修订评审提示以明确这一点，使用相同的固定校准材料复核；首次结果保留，不改成通过。此修订只涉及评审方法，不改 `SKILL.md`。

修订后的两项校准均符合事先声明的预期：无依据的“未运行测试”判为 fail，作者已提供而未附截图的验证记录判为 pass。校准只说明这两个检查点的分类符合预期，不代表评审器全面可靠。

## 验收要点的越界问题

第二版提示审查三个保留输出时，两项通过，`r5-holdout-02` 被判为 fail。理由是没有解释 `panel:prefs` 不存在时的代码分支。该分支确实出现在背景代码和检查要点中，但用户要求的是分别回复两条 review：解析失败后的旧值与字段保留，以及 migration 与整套测试状态。

复核采用两条路径，保留原案例及初判：

- 对同一份原任务、材料和成稿沿用第二版评审提示，仅移除检查要点；新的审查判为 pass、adequate。见 `criteria-probe/`。单次结果变化不能独立证明因果，但提示初判依赖检查项的可能。
- 原出题会话只查看自己编写的原案例，不看改稿或评审结果，复核哪些要求有原任务支持。它指出，逐项说明默认值分支、重复读取及所有测试数量都不是回复的必要内容；同时，“如报告测试”又把用户直接提出的整套测试问题设得太弱。完整意见见 [criteria-author-audit.md](criteria-author-audit.md)。这是出题者对标准的复核，不是外部人工评审。

据原任务与上述证据，将“必须解释无存储值分支”认定为过严的验收要求，不据此修改 skill。原始 `r5-cases.json`、成稿和失败记录均保持不动。这个案例的原检查项不能未经复核直接当作新的用户要求使用。

第三版单稿提示和成对提示同步明确：验收要点只是检查提示；遗漏是否重要取决于实际任务，用户直接提出的问题必须回答。保留对无依据新增事实的严格判断，不要求为每项作者陈述补外部证明。

第三版单稿校准三项均符合预期，包括新加入的反例：用户明确要求解释无存储值分支时，遗漏仍应判失败。成对校准两项也符合预期：未提供记录不能写成未测试；列出更多背景分支不能抵消把失败的整套测试写成通过。成对校准使用了一个已消费案例的成稿和维护代理构造的错误版本，只校准评审，不是新的 skill 对照实验。

按修订后的提示重新审查了同样的六份成稿，结果单独保存，不覆盖第二版审查。两种提示的计数分开报告。

## 结论与限制

本轮支持在当前六份材料上继续保留原 skill，不能据此声称中文质量提升或已达到最优。第二版到第三版的通过计数变化来自评审方法的修正，绝不是改稿变好了。成对校准也没有比较两版真实 skill。

样本是六份合成材料，使用同一模型家族且每项只生成一次。没有测量真实维护者的阅读时间、其他模型或所有中文表达；没有执行真实仓库调查、改文件或发布集成测试。所有案例已被消费，之后不能再作为未见测试。`r5-holdout-02` 的原检查要点有已知问题，复用前必须参照原任务和本轮复核。

后续继续以真实表达需要和新证据找问题。当前没有值得加进正文的新规则；评审方法的修正应帮助后续迭代避免为错误的评分增加冗余说明。
